# culinary-agents

Учебный проект ГПО: два небольших ИИ-компонента для кулинарного приложения.

1. **Food Search** — семантический поиск картинок блюд по текстовому запросу на русском языке.
2. **Ням Шеф** — консольный чат с кулинарным консультантом на локальной языковой модели (LM Studio).

Всё работает локально, без платных API.

## Как это работает

### Food Search (`search.py`)

```
запрос (ru) → перевод в en → текстовый вектор CLIP → косинусное сходство с индексом → top-k картинок
```

- **Модель:** OpenCLIP ViT-B/32. Текстовая часть — веса OpenAI, визуальная — по выбору: обычные OpenAI или дообученные на Food101 (`tanganke/clip-vit-base-patch32_food101`). Если веса Food101 не подошли, скрипт сам откатывается на OpenAI.
- **Индекс:** все картинки из `images/` один раз кодируются в векторы и сохраняются в `.pkl`. Дальше поиск — одно матричное умножение, поэтому запрос выполняется за доли секунды.
- **Перевод:** CLIP понимает английский лучше русского, поэтому запрос переводится. Порядок: кэш → Argos Translate (офлайн) → Google Translate (запасной) → исходный текст.
- **Устойчивость:** битые картинки пропускаются, повреждённый индекс пересобирается, ошибки перевода и загрузки весов не роняют программу.

### Ням Шеф (`qwen_cli_test.py`)

Консольный чат, который подключается к локальному серверу LM Studio (`http://localhost:1234/v1`) через OpenAI-совместимый API.

- Системный промпт задаёт роль консультанта, стиль ответов (2–5 предложений) и правила безопасности (несъедобное, сырое мясо, аллергии).
- Ответ выводится потоком, после него печатается статистика: время до первого токена, скорость в токенах в секунду.
- История обрезается пачкой, а не по одному сообщению, чтобы LM Studio не сбрасывал кэш начала промпта.
- Шлюз вежливости отсекает грубые сообщения до обращения к модели. Если рядом лежит модуль `polite_gate` с функцией `is_polite(text)`, используется он, иначе — простая проверка по корням слов.

## Быстрый старт

Нужен Python 3.10+.

```bash
git clone https://github.com/vvonderrr/culinary-agents.git
cd culinary-agents

python -m venv venv
venv\Scripts\activate          # Windows
# source venv/bin/activate     # Linux / macOS

pip install -r requirements.txt
```

### Food Search

1. Создайте папку `images/` рядом с `search.py` и положите в неё фотографии еды (`.jpg`, `.jpeg`, `.png`, `.webp`, `.bmp`, `.tiff`). Вложенные папки сканируются автоматически. Сам датасет в репозиторий не входит.
2. Запустите:

```bash
python search.py
```

При первом запуске скрипт сам построит индекс (на GPU это быстро, на CPU заметно дольше), скачает веса Food101 и русско-английский пакет Argos (около 100 МБ). Для этого нужен интернет, потом всё работает офлайн.

Параметры:

| Параметр | Что делает |
|---|---|
| `--variant food101\|openai` | Какие визуальные веса использовать (по умолчанию `food101`) |
| `--rebuild` | Пересобрать индекс, например после добавления картинок |
| `--top-k N` | Сколько результатов показывать (по умолчанию 3) |
| `--no-show` | Не открывать найденную картинку |

Пример:

```
Запрос: лазанья
🌐 Перевод: лазанья → lasagna
  1. [0.312] lasagna/12345.jpg
```

### Ням Шеф

1. Запустите LM Studio, загрузите модель и включите локальный сервер: вкладка **Developer → Start Server**.
2. Запустите:

```bash
python qwen_cli_test.py
```

Для выхода напишите `выход`. `Ctrl+C` во время ответа останавливает генерацию.

## Структура

```
search.py            поиск картинок блюд (CLIP + перевод)
qwen_cli_test.py     консольный чат «Ням Шеф»
requirements.txt     зависимости
images/              датасет (не в репозитории, см. выше)
*.pkl                индексы (создаются автоматически, не в репозитории)
```

## Что не входит в репозиторий

Датасет `images/`, индексы `*.pkl`, кэш переводов и виртуальное окружение исключены через `.gitignore`: они тяжёлые, а индексы и кэш пересоздаются кодом проекта.
